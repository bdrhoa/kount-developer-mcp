# Domain docs

Use a single context. Before exploring, read `GLOSSARY.md` at the
repository root and any relevant ADRs in `docs/adr/`. Read the
repository's accepted decisions in `DECISIONS.md` as directed by
`AGENTS.md`.

If the glossary or ADR directory is absent, proceed. Create domain
documentation as terms and architectural decisions are settled.

Use the glossary's terms in issues, proposals, hypotheses, and tests.
Surface conflicts with existing ADRs or accepted decisions and follow
the decision-change process in `AGENTS.md`.
